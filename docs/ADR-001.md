# ADR 001: CPU-first operational analytics MVP

Decision (updated 2026-11-04): consolidate the supported application in `coffee_ops`
and remove obsolete helpers and duplicate entry points. Use a specialized
Ultralytics detector with explicitly supplied weights, a class-aware constant-velocity
Kalman/Hungarian tracker, calibrated camera polygons, temporal state machines, an
append-only SQLite ledger, file/mock POS adapters, and a JSON CLI. No web service or
frontend is necessary for this MVP. One process owns one camera; SQLite serializes
writes. UTC capture time is distinct from processing time.

## Audit before implementation

Reviewed the root Python source, tests, requirements, example configuration and README.
The baseline automated suite passes 10 tests. No model weights, videos, labeled data,
or measured model evaluation are included. The directory is under a broader parent
Git worktree; changes must remain confined to this project.

* `app.py`: useful training/image helpers, but class names are overwritten on equal
  class count, counters are memory-only, spatial cooldown is not a movement ledger,
  and daily snapshots overwrite earlier sessions. The new package replaces it;
  actual CPU backend tests now verify that incompatible names are rejected.
* `tracker.py`: IoU and track record ideas are reusable. Kalman predictions are unused
  in association, prediction dt is fixed, expiration follows matching, and optional
  dependencies change behavior. Replace in the new pipeline with mandatory SciPy
  assignment, timestamp-based prediction, gating, expiry before association and caps.
* `daily_coffee_report.py`: invented CPU speed bonus and a heuristic readiness score.
  Replace with an actual persistent operational report.
* `final_report.py`: hard-coded training run/epoch and unconditional deployment claim.
  Replace with explicit held-out evaluation.
* `tests/`: port meaningful guardrails to the supported package. Remove tests whose
  only subjects are deleted legacy implementations. Test the real CPU worker too.
* Dataset helpers (`add_coffee`, `generate_labels`, `prelabel`, `remap_labels`,
  `sanitize_labels`, `fix_data_and_restore_labels`, `update_data_and_remap_by_filenames`,
  `split_train_val`, `list_label_stats`): local assumptions, destructive rewrites,
  filename-derived labels/random splits can leak correlated frames. These helpers
  are removed; manifest validation, grouped splits and extraction replace them.
* Training/setup/explanation/tuning/manual demo scripts (`prepare_and_train`,
  `setup_complete`, `explain_train_val`, `TUNING_GUIDE`, `retrain`, `test_*`,
  `tracker_demo`) are not deployment or acceptance evidence. Existing pinned
  dependencies were aligned with tested versions. The core includes SciPy and a
  matched Torch/TorchVision pair. Filenames above describe the historical audit.

## Options

| Approach | Decision and tradeoff |
|---|---|
| YOLO / RT-DETR + tracker | Select an explicitly trained YOLO-compatible model for existing tooling; RT-DETR can implement the same detector protocol. Localization, confidence and class IDs fit measurable ROI rules. CPU throughput must be measured locally. |
| VLM video reasoning | Defer to optional offline review/explanation. No latency, cost or localization benchmark here justifies primary frame-by-frame use. |
| SlowFast / action recognition | Defer: actions require clip annotations and do not establish payment. Adds temporal modeling before the event baseline is measured. |
| DeepStream / TensorRT | Defer: useful NVIDIA acceleration extension, but adds hardware/runtime packaging. Not a development dependency. |
| OpenCV only | Use for decoding, polygons and dataset utilities. Motion/background subtraction cannot reliably distinguish configured retail products. |

The tracker is a deliberately small SORT-style baseline, not a claim to match ByteTrack
or BoT-SORT on difficult crossings. Detector and tracker protocols permit replacements.
Fixed cameras are required: detected camera motion invalidates occupancy and resets
tracking, producing review health events. There is no face or cross-camera identity.

## Semantics and failure boundaries

Visual events are observations/inferences; POS paid quantities are the authoritative
sales ledger. Matching a visual event gives a likely association, not proof about a
person. Ambiguous order matches stay unresolved. A disappearance is never a sale.
Camera-only deployments cannot confirm payment. Idempotent replay requires the same
run ID, source, start time, configuration and model. State is rebuilt from the start;
completed events and frame records deduplicate transactionally. Mid-file resume is
deliberately unsupported. Different run IDs intentionally represent distinct sessions.

Synchronous replay applies backpressure with one frame in flight; live capture uses a
bounded newest-frame queue. Inference runs in a killable spawned process with timeouts.
No model download/fallback occurs in inference. Evidence references use source time
and frame index; optional JPEG evidence has a retention policy. Append-only events are
durable; snapshots are derived. Storage grows with history and needs managed retention.

## Robustness revision: 2026-11-04

Version 2 storage adds indexed current-order/latest-record projections, transactional
migration from version 1, nested savepoints and race-safe append. All SQL is inside
the storage adapter. Reconciliation queries at most two qualifying candidates and
commits 200-event batches. Unchanged POS/config contexts skip repeated matching.
Full-history reconciliation remains linear in event count; SQLite has one writer.

`runtime.py` owns leases, deadlines, heartbeats and cleanup; `pipeline.py` owns frame
processing. A failed write poisons in-memory state; recovery replays from frame zero.
Uncommitted evidence is removed. Allocation and reconciliation commit atomically.
Native NMS checks catch incompatible TorchVision binaries, including the host issue
found by the new test. A clean project virtualenv provides the verified CPU stack.

Synthetic stress reports explicitly include identity-loss cases beyond expiry and
distance gates. A tiny untrained network tests actual CPU adapter interoperability;
it is never used for model quality, promotion or shop-accuracy claims.
